Introduction

About

This documenation describes the pawaPay Mobile Money APIs which are developed and customized for Yango.

API Base URL

https://yango.pawapay.cloud/

Authentication

Our authentication mechanism requires clients to include a unique API key in the X-API-KEY field of the HTTP request header, providing a straightforward and secure method for data transactions.

Payout (Disbursement)

Send Money

You can disburse money from a Yango Partner's pawaPay wallet to an end user's mobile money wallet. After we have received a payout request, we send it to the mobile network operator (MNO). When the mobile network operator (MNO) finalizes your payout request, it will inform pawaPay. You check the status of your payout request through our Get Payout Status and Details endpoint.

Your payout request can have one of the following statuses in the pawaPay system:

Status Description
ACCEPTED The payout request has been accepted by pawaPay for processing.
SUBMITTED The payout request has been submitted to the mobile network operator (MNO) and is being processed.
COMPLETED The payout request has been successful. This is a final state.
FAILED The payout request has failed. This is a final state.

Get Status

To check the latest status of a transaction, you need to implement a status recheck mechanism using our Get Payout Status and Details operation.

Failure Codes

Technical failure codes

Technical failures should not happen during live operation and are intended to provide clear information during the development of the integration.

Failure Code Description
INVALID_RECIPIENT_FORMAT The financial address for the recipient is in an unrecognizable format. Please refer to recipient in Mobile Money Disbursement Request
INVALID_AMOUNT The amount is in an unrecognizable format. Please refer to amount in Mobile Money Disbursement Request.
AMOUNT_TOO_SMALL The specified amount is smaller than the minimum allowed by the mobile network operator (MNO) specified as the correspondent.
AMOUNT_TOO_LARGE The specified amount is larger than the maximum allowed by the mobile network operator (MNO) specified as the correspondent.
PARAMETER_INVALID An invalid parameter was found as part of the request.
AUTHENTICATION_ERROR The token specified for authentication is not valid or missing.
INVALID_INPUT The system was unable to parse the payload of the request.

Transaction failure codes

Transaction failures are expected to happen during live operation and are intended to provide clear information as to why a particular payment was not possible to complete.

Failure Code Description
BALANCE_INSUFFICIENT The balance of the Yango Partner's pawaPay wallet does not have the funds to initiate this payout.
RECIPIENT_NOT_FOUND The phone number (MSISDN) specified as the recipient, does not belong to the mobiler network operator (MNO) specified as the correspondent.
RECIPIENT_NOT_ALLOWED_TO_RECEIVE The recipient has reached a limit on their wallet that stops them from being able to accept this payout. Example: The customers wallet is able to hold up to 1 000 000 and the payout would take their balance over this limit.
OTHER_ERROR The payment failed due to an unknown error.
CORRESPONDENT_TEMPORARILY_UNAVAILABLE The mobile network operator specified as the correspondent is currently experiencing an outage and processing of payments has been temporarily halted. Please refer to our Status Page for live information about mobile netowrk operator availability.

Payouts

Payout Operations

Mobile Money Disbursement Request

Authorizations:
apiKeyAuth
path Parameters
accountId
required
string <uuid> = 36 characters

accountId of the Yango Partner which has been previously provided by pawaPay after partner's setup via PUT /v1/setup/account

Request Body schema: application/json
required
payoutId
required
string <uuid> = 36 characters

An UUIDv4 based ID specified by the merchant, that uniquely identifies the payout.

amount
required
string (Amount) [ 1 .. 23 ] characters ^([0]|([1-9][0-9]{0,17}))([.][0-9]{0,3}[1-9])...

The amount to be collected or disbursed. Please use a maximum of 2 decimal places.

Permitted samples:
5, 5.0, 5.00, 5.5, 5.50, 5.55, 0.5

Not permitted samples:
5., 5.55555, 5555555555555555555, .5, -5.5, 00.5, 00.00

msisdn
required
string (Msisdn)

The phone number of the receipient or payer. The format is (https://en.wikipedia.org/wiki/MSISDN).

MSISDN validation has following rules:

  1. Only digits without whitespaces or any other separators or prefixes like '+'.
  2. Should not start with zero.
  3. Country code is mandatory.
  4. Should not exceed or less than the valid length of specified country.

    Permitted samples for country code GHA:
    233558708954, 233558708955

    Not permitted samples for country code GHA:
    +233558708954, 233 558 708954, 233-558-708954, 0233558708954, 233558708, 233558708954872, 999558708954, 37255870895

statementDescription
string [ 4 .. 22 ] characters ^[a-zA-Z0-9 ]+$

The message that will be sent to the recipient of this payout.
